# L-02 classify.ts — 턴 판정·대기 시간

## 목적
턴 결과와 상태 diff로 턴 종류를 판정하고 대기 시간을 결정하는 순수 함수. 출력 grep에 의존하는 것은 sentinel과 limit 패턴뿐이며, 둘 다 상태 조건과 AND로 묶인다(결정 D6).

## 파일
- 구현: `src/loop/classify.ts`
- 테스트: `tests/unit/loop-classify.test.ts`
- depends: L-01 (`LedgerCounts`)

## 시그니처
```ts
import type { LedgerCounts } from "./ledger.js";
export type TurnKind = "complete" | "limit" | "crash" | "error" | "blocked" | "progress" | "idle";
export interface TurnInput {
  status: number | null;        // exit code
  signal: NodeJS.Signals | null;
  timedOut: boolean;            // runtime.ts가 timeout으로 kill한 경우
  tail: string;                 // 출력 마지막 부분(최대 4KB)
  sentinel: string;
  ledgerBefore: LedgerCounts; ledgerAfter: LedgerCounts;
  headBefore: string; headAfter: string;   // git HEAD sha
}
export interface Classification { kind: TurnKind; sentinelIgnored: boolean }
export function classifyTurn(i: TurnInput): Classification
export interface WaitKnobs { interval: number; limitBackoff: number; emptyBackoff: number; blockedBackoff: number; stallStreak: number }  // 초
export function waitFor(kind: TurnKind, stallStreak: number, k: WaitKnobs): number  // ms
```

## 판정 순서 (첫 매치)
1. `timedOut` 또는 (`status !== 0` && tail 공백뿐) → `crash`.
2. `status !== 0` → `error`. (sentinel이 있어도 무시: 정상 종료가 아님)
3. sentinel: `tail`의 마지막 5개 **비공백** 줄 중 `trim() === sentinel` 인 줄 존재 → 후행 원장 `unchecked === 0`이면 `complete`; 아니면 `sentinelIgnored = true`로 표시하고 아래로 계속.
4. progress 여부 = `headAfter !== headBefore` 또는 `after.checked > before.checked`.
5. `/usage limit|limit reached|rate.?limit/i` 매치 && !progress → `limit`.
6. `after.blocked > before.blocked` && !progress → `blocked`.
7. progress → `progress`. 그 외 → `idle`.

## waitFor

| kind | ms |
|---|---|
| limit | limitBackoff*1000 |
| crash | emptyBackoff*1000 |
| blocked, idle | stallStreak(호출자 누적) >= k.stallStreak ? blockedBackoff*1000 : interval*1000 |
| 그 외 | interval*1000 |

## 테스트 케이스 (테이블 주도)
- 각 kind 1개 이상 · 크래시(exit 1)+sentinel → error · exit 0 + sentinel + unchecked 잔존 → kind≠complete, sentinelIgnored=true · sentinel이 마지막 5줄 밖(6번째) → 무시 · sentinel 부분 문자열(`OMH_GOAL_COMPLETE!`) → 무시 · "rate limit" 텍스트 + HEAD 이동 → progress · timedOut → crash · BLOCKED 증가 + HEAD 이동 → progress · 아무 변화 없음 → idle · waitFor 표 전부, streak 미달 시 interval.
- **역검증**: 구현의 5번(limit) 조건에서 `!progress`를 지우면 "rate limit + HEAD 이동" 케이스가 실패해야 한다. 실패 확인 후 원복.
