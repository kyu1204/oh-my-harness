## 목적
루프 규칙을 한 곳에서 정의하고 프롬프트·CLAUDE.md 섹션·SKILL.md를 파생. 기존 `renderLoopProtocol`/`renderSkill`(loop-assets.ts)을 대체한다(제거는 L-11).

## 파일

- 테스트: `tests/unit/loop-protocol.test.ts`

## 시그니처
```ts
import type { LoopConfig } from "../core/merged-config.js";
export function loopRules(cfg: LoopConfig): string[]        // 규칙 문장 배열(각 1줄)
export function renderPrompt(cfg: LoopConfig): string        // 헤드리스 턴에 주는 프롬프트
export function renderProtocolSection(cfg: LoopConfig): string // "## Autonomous Loop Protocol"로 시작
export function renderSkill(cfg: LoopConfig): string         // frontmatter(name: omh-loop, description) + 본문
```

## 규칙 문장 (loopRules 순서 고정)
1. `Read <ledger> first; it is the single source of truth.`
2. `Pick the next unchecked task and implement it exactly as its work order in <workOrders>/<ID>.md says. Make no design decisions.`
3. `No work order, no work: mark the task "BLOCKED: no work order" and stop. Never write your own work order.`
4. `Run the work order's acceptance commands before ticking any checkbox.`
5. `Architect-only, never edited by the loop: <architectOnly 목록 백틱, 비면 "none declared">.`
6. `If a task needs a human, or after three failed attempts, mark it "BLOCKED: <reason>" and move on. Never idle waiting for a person.`
7. `One task, one commit; update the checkbox and the progress log in the same commit.`
8. `Print exactly <sentinel> as the final line ONLY when every task is done and verified; otherwise never mention that string in any form.`

## 렌더러 요구
- `renderPrompt`: 규칙 전부 포함 + 첫 줄 `Autonomous loop iteration.` 주석(코드)에 명시: 프롬프트에 `BLOCKED:` 리터럴이 있어도 판정은 원장 diff 기준이라 무해(D6).
- `renderProtocolSection`: 첫 줄 `## Autonomous Loop Protocol`, 규칙 불릿, 끝에 운영 3줄: `Start: omh loop start` / `Watch: tail -f .omh/state/loop/runs/<runId>/events.jsonl (omh loop status prints the path)` / `Stop: omh loop stop`.
- `renderSkill`: frontmatter `name: omh-loop`, `description: Set up and start the autonomous loop for a goal. Use when asked to run work as a loop, in a loop, or unattended.` 본문: 아키텍트 5단계(원장 작성 → 지시서 작성(코드 밖 부수작업 포함, 여러 개 미리) → architectOnly 지정 → `omh loop start` → 즉시 모니터 부착 `omh loop status` + `tail -f`, 실패 시그니처 감시) + 규칙 섹션.

## 테스트 케이스
- 세 렌더러 출력 모두가 `loopRules(cfg)`의 모든 문장을 포함(문장 단위 `toContain`).
- architectOnly `["ios/Runner.xcodeproj"]` → 세 출력 모두에 그 경로 그대로.
- 스킬에 `omh loop start`, `omh loop status`, `tail -f .omh/state/loop/runs/` 포함, `nohup`·`run.sh` 미포함.
- 섹션 첫 줄이 `## Autonomous Loop Protocol`.
- 프롬프트 마지막 규칙에 sentinel 값 포함.
