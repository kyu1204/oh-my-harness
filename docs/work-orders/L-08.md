# L-08 supervisor.ts — 반복 오케스트레이션

## 목적
한 run의 전체 수명: 잠금 → worktree/시드 → 시그널 핸들러 → 반복(stop 확인 → 자산 동기화 → 스냅샷 → 턴 → 판정 → 이벤트 → 대기) → 해제.

## 파일
- 구현: `src/loop/supervisor.ts`
- 테스트: `tests/unit/loop-supervisor.test.ts` (in-process; L-09에서 매트릭스 추가)
- depends: L-01~L-07

## 시그니처
```ts
import type { LoopConfig } from "../core/merged-config.js";
import type { TurnOptions, TurnResult } from "./runtime.js";
export interface SupervisorDeps { runTurn: (o: TurnOptions) => Promise<TurnResult>; sleep: (ms: number) => Promise<void>; now?: () => Date }
export interface SupervisorOptions { projectDir: string; cfg: LoopConfig; runId: string; maxIterations?: number }
export type SupervisorExit = "complete" | "stopped" | "already-running" | "failed";
export async function runSupervisor(o: SupervisorOptions, deps: SupervisorDeps): Promise<SupervisorExit>
```

## 흐름
1. `acquireRun(projectDir, {runId, pid: process.pid, startedAt, runtime: cfg.runtime, iteration: 0, cwd})` 실패 → `appendEvent(kind:"already-running")` → return `"already-running"`.
2. `cwd = cfg.isolate ? (await ensureWorktree(projectDir)).path : projectDir`; isolate면 `seedLedger`(이벤트 `seeded`/`worktree-reused`). WorktreeError → 이벤트 `failed` + releaseRun → return `"failed"`.
3. 시그널: `process.once("SIGTERM"|"SIGINT")` → 동기: childPid 있으면 `process.kill(childPid,"SIGTERM")`, 이벤트 `stopped`, releaseRun, `process.exit(143)`. (테스트에서는 `maxIterations`로 종료하므로 핸들러 등록 여부만 확인)
4. `appendEvent(kind:"start")`, `streak=0`, `iteration=0`.
5. 반복:
   - stop 플래그 존재 → `stopped` 이벤트, break.
   - isolate면 `syncAssets` (throw → `failed`).
   - 스냅샷: `ledgerBefore = parseLedger(read(cwd/ledger))`, `headBefore = headOf(cwd)`.
   - `iteration++`; `updateRun({iteration})`; `logPath = turnLogPath(...)`(mkdir -p).
   - `runTurn({argv: buildTurnArgv(cfg.runtime, cfg.model, renderPrompt(cfg)), cwd, env: {...process.env, OMH_LOOP:"1", OMH_LOOP_RUN_ID: runId}, logPath, timeoutMs: cfg.turnTimeout*1000, shouldStop: () => existsSync(stopFlag), onSpawn: pid => updateRun({childPid: pid})})`.
   - 스냅샷 after → `classifyTurn`. `sentinelIgnored`면 이벤트 `sentinel-ignored`.
   - 이벤트 `kind`(complete/limit/crash/error/blocked/progress/idle) + message + meta(status, ticked, newBlocked, head).
   - `complete` → break, exit "complete". `stoppedByRequest` → `stopped`, break.
   - streak: blocked/idle → +1, 그 외 → 0. `waitMs = waitFor(kind, streak, cfg)`; streak 도달 시 이벤트 `waiting`.
   - `maxIterations` 도달 → break(`stopped`).
   - `deps.sleep(waitMs)`.
6. `releaseRun`, return.

## 테스트 케이스 (L-08 범위: 뼈대)
- temp git repo + 원장 1태스크 + `isolate:false`; stub runTurn이 원장을 체크·커밋하고 tail에 sentinel → exit "complete", 이벤트에 start·progress 또는 complete, run.json 삭제됨.
- 두 번째 `runSupervisor`(같은 dir, run.json을 살아있는 것으로 미리 기록) → "already-running".
- sleep 스텁이 받은 ms 기록 → interval*1000.
