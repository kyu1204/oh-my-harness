## 목적
판정·백오프·격리·정지의 실제 동작을 in-process로 봉인. stub `runTurn`이 temp repo를 **실제로** 변경한다(파일 체크, 커밋, BLOCKED 표기).

## 파일

- depends: L-08

## 헬퍼
`makeRepo({tasks, isolate})`, `turnScript(fn)`: fn(cwd, iteration)이 repo를 조작하고 `{status, tail}` 반환. `sleepSpy`가 대기 ms 배열 수집. `maxIterations`로 종료.

## 케이스 (각각 기대 이벤트 kind 시퀀스와 sleep ms를 단언)
1. complete: 턴1 체크+커밋+sentinel → [start, complete].
2. 크래시 후 sentinel: 턴1 status 1 + sentinel → error; 턴2 정상 → complete.
3. 미완료 잔존 + sentinel: 2태스크 중 1개만 체크하고 sentinel → sentinel-ignored + progress; 계속 실행.
4. limit: tail "usage limit reached", 변화 없음 → limit, sleep = limitBackoff*1000.
5. BLOCKED via ledger ×3: 매 턴 원장에 `BLOCKED:` 1줄 추가(커밋 없음) → blocked, blocked, waiting → 3번째 sleep = blockedBackoff*1000.
6. idle ×3: 아무 변화 없음, status 0 → idle ×3, 3번째 sleep = blockedBackoff*1000 (BLOCKED 텍스트 없이도).
7. 긴 턴 중 stop 플래그: runTurn stub이 `shouldStop()` 폴링을 흉내 내 플래그 생성 후 `stoppedByRequest:true` 반환 → stopped, exit "stopped".
8. 동시 2개: `Promise.all([runSupervisor A, runSupervisor B])` → 하나 "already-running".
9. stale run.json(pid 999999) 미리 존재 → 정상 시작(회수), 이벤트 start.
10. 실행 중 disable: isolate true로 시작해 1턴 후(maxIterations 1) generate(loop off) 호출 → run.json 없음, worktree 디렉터리 없음. (L-11 이후 활성; 그 전엔 `it.todo`)
11. 시드/재시드: isolate true; 첫 run seeded; worktree 원장 체크 후 같은 메인 원장으로 재run → 체크 유지; 메인 원장 수정 후 재run → 재시드.
12. **프롬프트 에코**: stub이 tail에 `renderPrompt(cfg)` 전문(`BLOCKED:` 리터럴 포함)을 출력하되 원장·HEAD 불변 → kind는 idle(blocked 아님), 이벤트에 blocked 0건.
