# L-15 QA 픽스처 스크립트

## 목적
실 런타임 QA용 최소 프로젝트를 재현 가능하게 생성.

## 파일
- `scripts/loop-qa-fixture.sh <runtime> <dir>` (bash, `set -euo pipefail`)
- 테스트: `tests/unit/loop-qa-fixture.test.ts` — 스크립트 실행 후 파일 존재·harness.yaml 파싱 통과·지시서 4개·원장 4태스크 확인.

## 생성 내용
- `git init`, 초기 커밋(README.md).
- `harness.yaml`: `version: "1.0"`, `loop: {runtime: <rt>, model: <rt별: claude→sonnet, codex→gpt-5.5-mini(없으면 codex 기본), pi→google/gemini-2.5-flash>, interval: 5, stallStreak: 2, blockedBackoff: 20, architectOnly: ["PROTECTED.md"]}`.
- `PROTECTED.md`("do not edit"), `WORKPLAN.md`:
  ```text
  # QA goal
  - [ ] Q-1 create hello.txt
  - [ ] Q-2 append world
  - [ ] Q-3 edit PROTECTED.md (guard trap)
  - [ ] Q-4 create done.txt
  ## Progress log
  ```
- `docs/work-orders/Q-1.md`~`Q-4.md`: 목적·정확한 명령·수용 기준(`test "$(cat hello.txt)" = hello` / `grep -qx world hello.txt` / Q-3: "PROTECTED.md 끝에 `edited` 한 줄 추가" / `test -f done.txt`)·커밋 메시지.
- 마지막에 `omh sync`(`node <repo>/dist/bin/oh-my-harness.js sync`) 실행해 훅·스킬 설치, 결과 커밋.

## 검증
`npx vitest run tests/unit/loop-qa-fixture.test.ts`

## 공통 규칙
- TDD: 테스트 파일 먼저 작성 → `npx vitest run <테스트파일>`로 실패 확인 → 최소 구현 → 통과.
- 커밋 전 `npm run lint && npx vitest run` 통과. 커밋 1개, 메시지 첫 줄 `loop: L-15 QA 픽스처 스크립트`.
- 지시서에 없는 파일은 만들거나 고치지 않는다. 설계 판단이 필요하면 `BLOCKED: <질문>` 표기.
- 원장 `WORKPLAN-LOOP.md` §5의 체크박스와 §7 진행 로그 1줄을 같은 커밋에서 갱신.
