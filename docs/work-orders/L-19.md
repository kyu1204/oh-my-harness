# L-19 loop-guard: Codex apply_patch 페이로드 차단

## 목적
Codex는 파일 편집을 `tool_name: "apply_patch"` + `tool_input.command`(패치 텍스트)로 전달한다. loop-guard는 `file_path`와 Bash 휴리스틱만 보므로 `*** Update File: PROTECTED.md`를 통과시켰다(실 QA 2026-08-26 확인). path-guard와 같은 방식으로 헤더에서 경로를 추출해 검사한다.

## 파일
- `src/catalog/blocks/loop-guard.ts` (template만)
- 테스트: `tests/unit/loop-guard.test.ts`

## 변경
- `TOOL_NAME=$(jq -r '.tool_name // empty')`. `TOOL_NAME == apply_patch`이면 `.tool_input.command`에서 `^\*\*\* (Add|Update|Delete) File: (.+)$` 헤더 경로들을 수집(CRLF 제거, path-guard.ts:30-39 패턴 그대로).
- 수집된 각 경로에 `_omh_path_under`를 적용해 work-orders / architectOnly 검사. Bash 휴리스틱은 `apply_patch`가 아닌 경우에만 적용.
- runGuard 헬퍼가 `toolName`을 받을 수 있게 확장.

## 테스트 케이스
1. apply_patch 페이로드로 `*** Update File: PROTECTED.md` (architectOnly=["PROTECTED.md"]) → block.
2. `*** Add File: docs/work-orders/T-9.md` → block (자가 작성).
3. `*** Update File: src/app.ts` → allow.
4. 패치 텍스트가 `BLOCKED:`나 `tee` 같은 단어를 포함해도 경로가 보호 대상이 아니면 allow (휴리스틱 미적용 확인).
5. CRLF 헤더도 block.
