# L-21 종료 시 프로세스 그룹 잔존자 정리

## 목적
Codex 턴이 자기 그룹에 데몬(`SkyComputerUseClient`)을 남겨 슈퍼바이저 종료 후에도 pgid가 살아 있었다(실 QA). 슈퍼바이저는 **그룹 리더일 때만** 정상 종료 직전 그룹의 나머지에 SIGTERM을 보낸다.

## 파일
- `src/loop/stop.ts`: `export function isGroupLeader(pid = process.pid): boolean` — `ps -o pgid= -p pid`가 pid와 같으면 true(실패 시 false). `export function sweepOwnGroup(): void` — 리더가 아니면 no-op; 리더면 SIGTERM 핸들러를 무시(no-op)로 잠시 설치 → `process.kill(-process.pid,"SIGTERM")` → 핸들러 원복. 자신은 죽지 않는다.
- `src/cli/commands/loop.ts` `loopRunCommand`: `runSupervisor` 반환 후 `sweepOwnGroup()` 호출(주입 가능 `sweepImpl`).
- 테스트: `tests/unit/loop-stop.test.ts`에 isGroupLeader(현재 프로세스는 false; `detached` bash 자식에서 `ps` 로 true 확인은 e2e), `tests/unit/loop-e2e.test.ts` 완료 케이스에 "완료 후 그룹 소멸(`kill -0 -pid` ESRCH)" 단언 추가 — stub claude가 `nohup sleep 300 &`로 잔존자를 남기도록 변경.
- `tests/unit/cli-loop.test.ts` run 케이스: `sweepImpl` 스파이가 호출됨.

## 검증
`npx vitest run tests/unit/loop-stop.test.ts tests/unit/loop-e2e.test.ts tests/unit/cli-loop.test.ts`
